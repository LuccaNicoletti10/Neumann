# ADR-0020: Function reads are history.asOf

- Status: accepted
- Date: 2026-08-20
- Deciders: Neumann kernel maintainers
- Contracts touched: `packages/contracts/src/v1/function-runtime.ts` (`FUNCTION_SNAPSHOT_UNAVAILABLE`)
- Packages touched: `function-registry`, `platform-api`
- Does not alter: `0001`–`0025`, ADRs 0001–0019
- Closes follow-up of ADR-0019: temporal `readAsOf`

## Context

ADR-0019 persisted `readAsOf` on every Function execution but `FunctionObjectReader` called `objects.get`. The Function observed the live row. A later update or delete could change what a pending execution would see if create raced the clock, and `readAsOf` did not control the read.

`ObjectHistoryStore.asOf` is already the kernel temporal authority (PEÇA 3 / governed objects). A second time-travel store would be a duplicate.

## Decision

Function object reads go only through `ObjectHistoryStore.asOf(ontologyId, objectTypeId, primaryKey, readAsOf)`.

- `readAsOf` is generated by the server clock at `FunctionRuntime.create`. Callers cannot supply it.
- The same instant is used for every object ref on that execution.
- Policy `canReadObjectType` and current `redactProperties` run on the historical properties.
- Missing or deleted asOf row → `FUNCTION_SNAPSHOT_UNAVAILABLE`. No execution row at create; at `runOnce`, CAS to `FAILED` with zero sandbox and zero Action.
- Live `objects.get` is forbidden on this path. There is no fallback to the current row.
- `runOnce` reloads via `asOf(readAsOf)` so current redaction applies to the pinned instant.

## Consequences

### Positivas

- Update/delete after create cannot change the Function's input.
- Restart with a new pool still sees v1 if `readAsOf` predates v2.

### Negativas / custo

- Objects written outside the governed repository have no history row and fail closed.

## Invariantes que os testes devem provar

- `objects.get` is absent from Function reads.
- v1 → create execution → update v2 → delete → restart → Function receives v1 redacted.
- Unavailable snapshot does not start the sandbox or invoke Actions.

## Alternatives considered

### Alt A — Keep live `objects.get` and freeze JSON at create

Rejected. `readAsOf` would remain a stored timestamp that does not control the read. A race between `clock()` and `get()` would snapshot v2 under an earlier `readAsOf`.

### Alt B — A Function-specific temporal table

Rejected. Duplicates `platform_object_history` / `ObjectHistoryStore.asOf`.

## Follow-up

Privileged HTTP for artifact publish. Process/container isolation if untrusted authors are ever allowed.
