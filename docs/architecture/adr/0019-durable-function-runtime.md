# ADR-0019: Durable governed Function Runtime

- Status: accepted
- Date: 2026-08-19
- Deciders: Neumann kernel maintainers
- Contracts touched: `packages/contracts/src/v1/function-runtime.ts` (`FunctionExecutionPin`, `FunctionRuntime`, `FunctionArtifactStore`), `packages/contracts/src/v1/ontology.ts` (`FunctionTypeDef.artifactHash`)
- Packages touched: `function-registry`, `platform-api`, `execution-sandbox`, `ontology-registry`
- Migration: `infra/sql/0025_function_runtime.sql`
- Does not alter: `0001`–`0024`, ADRs 0001–0018

## Context

Functions were a process-local `FunctionRegistry` (`Map` of in-process implementations). HTTP invoked them synchronously, could pass raw object properties, and could not survive restart or run on a second replica. That is not an operational kernel: a Function is a pinned computation over SecureReads, and any mutation must go through `ActionExecutor`.

## Decision

One execution path:

```
OntologyVersion → FunctionDefinition pin → immutable artifact (SHA-256) → FunctionRuntime → SecureReads / ActionExecutor
```

Authorities:

| Decision | Authority |
|---|---|
| Function metadata / version | `OntologyVersion.functionTypes` (`artifactHash` on `FunctionTypeDef`) |
| Artifact bytes | `FunctionArtifactStore` (PostgreSQL `function_artifacts`) |
| Pin at create | `FunctionDefinitionResolver.pin` (may read latest **only here**) |
| Execution | `FunctionRuntime` (`create` / `get` / `cancel` / `runOnce`) |
| Object reads | `FunctionObjectReader` via `history.asOf(readAsOf)` + current redaction (ADR-0020) |
| Mutations | `ActionExecutor.apply` with idempotency `fn:{functionExecutionId}:{step}` |
| Isolation | `execution-sandbox` `runInWorker` (worker_threads + vm) |
| HTTP | `routes/functions.ts` calls only `FunctionRuntime` |

`createFunctionRegistry` remains CLI/demo. `platform-api` must not import it.

Pin persisted on every execution:

```
ontologyId, ontologyVersionId, functionId, functionVersion,
artifactHash, inputSchemaHash, outputSchemaHash
```

`FunctionRuntime.runOnce` never calls `getLatestVersion`. A later FunctionType publish does not change an existing pin or retry.

State machine (CAS): `PENDING → RUNNING → SUCCEEDED | FAILED | DENIED | CANCELLED`. Terminal does not reopen.

Idempotency scope: `ontologyId + principal + functionId + idempotencyKey`. Same scope + same `requestHash` → replay. Same scope + different hash → `FUNCTION_IDEMPOTENCY_CONFLICT`. Different principals are isolated.

## Threat model (real isolation)

**Publishers.** Artifact publish is not a public HTTP route. Bytes enter through `FunctionArtifactStore.publish` (privileged composition-root / operator). FunctionType attach is an ontology draft commit (`ontology.write`). This is **semi-trusted** code: authored by ontology publishers, not arbitrary tenants.

**Not a hostile-code sandbox.** Isolation is `worker_threads` + `vm` + static forbidden-API scan at publish, empty FS allowlist, `allowNetwork: false`. Worker threads are **not** a security boundary against a determined hostile author (they share the host kernel, can attempt to exhaust the process, and `vm` is not a jail). If Neumann ever accepts untrusted Function source, the boundary must be a process or container with OS limits. This ADR does not implement that.

Blocked at publish (scan) and/or worker: `require` / dynamic `import`, `eval` / `new Function`, `child_process`, `process`/`env`, `fs`/`net`/`http`, native modules, ambient `Date.now` / `Math.random`. Host injects pinned `now` (the persisted `readAsOf`) and a PRNG seeded from `executionId`.

Limits: wall/CPU timeout, worker old-space, output bytes, log bytes. First causal failure wins (ADR-0002): `TIMEOUT`, `MEMORY_LIMIT`, `FORBIDDEN_API`, `EXECUTION_ERROR`, `OUTPUT_LIMIT`, `CANCELLED`.

## Reads, redaction, mutations

Create authorizes the Function resource (`allow` only; `partial`/`deny` do not execute). Object refs are resolved through SecureReads-shaped `FunctionObjectReader`. Hidden-miss if the type or object is unreadable. `redactProperties` runs **before** the snapshot is stored and before the sandbox. The Function never receives a hidden property.

`readAsOf` is generated by the server clock at create and is the asOf instant for every object ref (ADR-0020). Live `objects.get` is not on this path.

Functions do not import `ObjectRepository`, SQL, or `ProjectionWriter`. If the artifact returns `{ actions: [...] }`, the **host** calls `ActionExecutor.apply` with the execution principal and a derived idempotency key. Crash after Action commit and before Function result persist replays the same key — no duplicate mutation.

## Worker and HTTP

`createFunctionWorker` claims via CAS SQL (`SKIP LOCKED`), recovers expired leases, uses `AbortSignal`, limits concurrency, and does not listen HTTP. It starts only after `ctx.ready`. HTTP: create `202`, get, cancel. Hidden-miss for unreadable Functions.

## Consequences

### Positivas

- Restart and replica execute the stored pin and hashed bytes.
- Policy revoke before sandbox → `DENIED`.
- One Function authority on the product path.

### Negativas / custo

- Isolation is semi-trusted, not hostile.
- Artifact publish has no public HTTP API yet.

### Invariantes que os testes devem provar

- Artifact hash determinism, reuse, immutability (SQL UPDATE/DELETE fail).
- Pin survives a newer FunctionType; retry does not resolve latest.
- `partial`/`deny` do not start the sandbox; redaction precedes it.
- Idempotent replay / conflict / principal isolation.
- Two workers, one claim; expired lease resumed; terminal CAS.
- Crash after Action does not duplicate; PG restart without reseed.

## Alternatives considered

### Alt A — Keep process-local `FunctionRegistry` on HTTP

Rejected. Does not survive restart and duplicates the ontology FunctionType.

### Alt B — Let Functions write repositories

Rejected. Violates ADR-0005. Mutations stay on `ActionExecutor`.

### Alt C — Claim worker_threads is a hostile sandbox

Rejected. The isolation does not match that claim. Semi-trusted + honest threat model.

## Migration

Append-only `infra/sql/0025_function_runtime.sql`. Do not edit `0001`–`0024`.

## Follow-up

Privileged HTTP for artifact publish. Process/container isolation if untrusted authors are ever allowed. Temporal `readAsOf` is ADR-0020.
